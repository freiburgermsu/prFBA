## 0. Summary

- **What actually moved.** The data changed: the shared PGFam cache (1,006 entries), the deployments' tie-set
  caches, 15 genome dicts and the E3 catalogue. The fetchers changed too (paging past 25,000 rows, PATRIC-only,
  own-genome ids). **No scoring code used by the committed results changed after those results were made**,
  with three exceptions:
  - `select_references.py` 7153311 (2026-10-20), which touches only the fetch path;
  - `pfunc_estimator.py` (build path only, not the gate's formula);
  - the aligner, which is byte-identical where checked.

  So this re-score is a re-run of everything downstream of BV-BRC gene data. Alignments and 16S work are reused.
- **What it touches.** Of the 302 inventory items, 178 depend on the changed data. Of those:
  - 155 are re-scored by existing code;
  - 9 need small new derivation scripts, because no committed file holds them (W6 also computes 4 deck constants);
  - 7 are already current (the deployments);
  - 6 depend on decision D1 (the shared-reference panel);
  - 1 depends on decision D7.

  The other 124 items provably do not move (section 6). Items are counted per inventory, so a claim that two
  inventories both list counts twice.
- **Five runs.**

  | run | content | wall time |
  |---|---|---|
  | Run 1 | Every cache writer, plus controls; the KBase upload starts in parallel | ≈ 7–8 h |
  | Run 2 | Every cache reader: E3 gate, MAG re-score, cross-panel downstream, both as-shipped PICRUSt2 chains (network), depth probe | ≈ 3.5–4.5 h |
  | Run 3 | Shared reference, Path A part 1: refs, PICRUSt2 and prFBA folds, C2, family, score pass 1 | ≈ 5–6 h |
  | Run 4 | Phenotype passes, score pass 2, post-hoc studies | ≈ 5 h |
  | Run 5 | Derivation scripts, figures, decks, docs, baseline re-stamp, manuscript | ≈ 3–5 h |

  The total is **about 24–29 h of wall time**, plus the KBase upload (3–7 h, in the background from the end of
  Run 1). Path B (re-planning the shared-reference panel) would replace Runs 3–4 with about 1.5–2 days.
- **Decisions.** Ten decisions are listed in section 1, each with a recommended default. The two that change the
  most text are:
  - **D1**: keep the pre-registered shared-reference panel (Path A) and disclose it, or re-plan (Path B);
  - **D2**: re-select the depth-20 legacy tree with today's code, which differs from the June code.

## 8. Hazards checklist (each one has bitten before)

- Checkpoints are "output exists". Every stale output must be moved aside (to `$W/pre_repair`) or the stage
  silently keeps it: P7, the MAG drivers, the run_picrust2 selections, `_cache_*` and refs, launchers that refuse
  to overwrite.
- `--force` means re-align or rebuild trees in the shared reference. The d100 drivers refuse `--force`. The d20
  drivers accept it and would switch the d20 original to the union rule and re-align (H5): use them by hand only.
- One cache writer at a time. The flock covers only the d100 drivers, so take it by hand in R1.4. Freeze after R1.6.
  Any write makes the catalogue stale, and the gate then refuses.
- Built-in reproduction checks invert meaning after the repair: E1 and the gate fail until P7 is re-run. Order:
  P7 → E1 → gate.
- Hard links: `data_family/{panel_eligible,panel_ec_universe,neighbors,prepass_*}.json` share inodes with `data/`.
  W3 writes only `_cache_panel_ec.json` (a separate copy), so the links survive. Check the inode.
- Removing `post.done` closes the gates of `run_picrust2_d100.sh` and `run_downstream_d100.sh` until all six trees
  pass again. That is why R2 follows R1.
- PDFs and gzip carry dates: compare pixels and decompressed content.
- `phenotype_fold` resumes rows of an old genome set; use fresh canonical directories.
- `controls.json` merges modes: re-score C1 (optional), then C2, then pass 1, then pass 2.
- Swap is full; the journal must record each unit's memory peak. Two runs of the same 40 GB loader must not overlap
  with the POST.
- Do not touch `presentations/*_2026-10*.pptx` or the untracked user-edits deck. Do not `git add -A` in the
  deployment repos (36 GB of SYN directories are untracked there).
